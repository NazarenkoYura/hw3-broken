Контаминация: где ломается всё

  • Утечка не роняет пайплайн и не видна в логах. Она видна только как подозрительно хорошая метрика на тесте
  • Случайный сплит дал 19,5% утечки. Сплит по темам — всё ещё 12,3%: одна и та же формулировка встречается в разных темах
  • Ноль получается только после дедупликации: сначала схлопнуть одинаковое, потом резать по группам
  • Проверка контаминации — отдельная стадия пайплайна, а не разовый скрипт «посмотреть глазами»

Валидация схемы как ворота

  • Схема описывается один раз (pydantic, pandera) и применяется до любой обработки

Лекция 3 · Слайд 7/11

Почему git не годится для данных

  • Git хранит каждую версию целиком. Три правки датасета на 50 МБ — это 150 МБ, которые останутся в истории навсегда
  • Diff по бинарнику бесполезен, merge невозможен, clone растёт линейно
  • Git LFS решает половину: файлы уезжают из истории, но версионирование остаётся ручным и не связано с кодом, который их произвёл
Лекция 3 · Слайд 8/11

DVC: где на самом деле лежат данные

  • В git попадает только .dvc-файл — сотня байт с хэшем и размером
  • Хранилище content-addressable: имя файла в кэше — это его хэш. Одинаковое содержимое лежит один раз, даже если в проекте оно под пятью именами
  • dvc push отправляет кэш в remote, dvc pull забирает. dvc checkout подставляет в рабочую папку ту версию, которая записана в текущем коммите
  • Отсюда главное свойство: коммит однозначно определяет данные. Переключились на коммит месячной давности — получили тот датасет
DVC — Data Version Control Обычная программа на Python, а не сеть и не блокчейн. Ставится пакетом, работает локально, сама никуда ничего не отправляет. Хэш нужен ровно для того же, для чего в git: адресовать файл по содержимому. Ни майнинга, ни токенов, ни распределённого реестра. Remote — тоже просто место: папка, сетевой диск, S3. В ДЗ 3 это папка dvc_remote/ рядом с проектом. 
# ставится обычной зависимостью проекта
uv add dvc            # или pip install dvc
dvc init              # завести .dvc/ в репозитории
dvc repro             # пересчитать пайплайн
dvc push / dvc pull   # в remote и обратно
dvc checkout          # разложить версию из коммита
Лекция 3 · Слайд 9/11

Пайплайн: dvc.yaml

  • Стадия пересчитывается, когда изменились deps или params. Забыли указать код в deps — правите скрипт, а DVC говорит «всё свежо»
  • dvc repro проходит граф, dvc dag его рисует, dvc metrics diff показывает, что изменилось между версиями
  • Provenance целиком: коммит → версия данных → метрики → артефакт. Это и есть ответ на вопрос «а на чём обучалась та модель, что сейчас в проде»

Право, лицензии, datasheet

Прежде чем качать

лицензия источникаCC-BY требует указать автора, CC-BY-NC запрещает коммерческое использование. «Выложено в интернете» лицензией не является. У датасета в ДЗ 3 — CC-BY-4.0, и это записано в SOURCE.md
персональные данныеФИО, телефоны, адреса, номера документов. Удалять на стадии чистки, а не «потом посмотрим»: модель запоминает и воспроизводит их дословно
условия использования сайтаОтдельно от лицензии на контент. Запрет на автоматический сбор — это запрет, даже если технически всё получается
