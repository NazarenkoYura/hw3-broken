# Datasheet: Cross Validated → SFT-чат по статистике и ML

## Назначение

Набор для дообучения языковой модели в формате chat: вопрос пользователя по статистике или машинному обучению и развёрнутый ответ ассистента. Модель в ДЗ 3 не обучается — датасет готовится так, чтобы на нём не стыдно было учить.

Тема закреплена за этим репозиторием: **вопросы и ответы Cross Validated (stats.stackexchange.com)** — статистика, вероятность, регрессия, ML.

## Источник

Сырьё — публичная выгрузка Stack Exchange для сайта Cross Validated:

| Файл | Роль |
|------|------|
| `dataset/Questions.csv` | вопросы: `Id`, `Title`, `Body` |
| `dataset/Answers.csv` | ответы: `Id`, `ParentId`, `Score`, `Body` |
| `dataset/Tags.csv` | теги вопроса: `Id`, `Tag` |

Это чужой готовый набор. Сдачей он не является: стадия `collect` его **перерабатывает**, и каждое действие видно числом в `metrics/collect.json`.

## Лицензия

Контент Stack Exchange распространяется по **CC BY-SA 4.0**. Производный датасет наследует ту же лицензию: при использовании нужно указывать авторство сообщества Cross Validated / Stack Exchange и распространять производные на тех же условиях.

Исходные CSV и артефакты `data/*.jsonl` **не коммитятся** в git; версионируются через DVC (`dvc.yaml`, локальный remote `../dvc_remote`).

## Что сделано руками (не «скачал и переименовал»)

1. **Сужение.** Оставлены 125 тегов статистики и ML (`collect.topics`). Вопросы с другим первичным тегом отбрасываются.
2. **Переразметка.** На вопрос берётся только лучший ответ с `Score ≥ collect.min_answer_score` (сейчас 1). Нет такого ответа — вопрос не попадает в обучение.
3. **Обогащение.** В источнике системной инструкции нет. Добавлены 5 вариантов `collect.system_prompts`; вариант выбирается детерминированно по `sha1(id)`, чтобы `raw.jsonl` был воспроизводим.
4. **Контракт.** HTML тел вопросов/ответов снимается, запись пишется как `{"id", "topic", "messages": [system, user, assistant]}`.

## Сплит

Ключ группы: `split.group_key = topic` (нормализованный первичный тег). Все примеры одной темы целиком уходят в один сплит — иначе вопросы-парафразы одной темы разъезжаются по train и test, и метрика на test врёт.

Доли: train 0.8 / val 0.1 / test 0.1, seed 42. Раскладка жадная: группы от крупных к мелким в сплит с наибольшим остатком ёмкости.

Проверка контаминации (стадия `split` и отдельно `scripts/check_contamination.py`): пересечение по id, по нормализованному тексту, по группам и near-dup (MinHash, порог Жаккара 0.85 — тот же, что в `clean.near_dup`). На v1 и v2 все четыре счётчика равны **0**.

## Известные ограничения

- Язык почти целиком английский: это не русскоязычный НМО-датасет из шаблона курса.
- Тема примера — **первый** тег вопроса в выгрузке, не полный список тегов. Один вопрос может относиться к нескольким областям.
- `Score ≥ 1` не гарантирует корректность: это голоса сообщества, а не экспертная переразметка.
- Снятие HTML оставляет текст, но ломает вёрстку формул и часть разметки кода.
- Потолок `max_per_topic` режет популярные теги (`r`, `regression` и т.д.), чтобы ни одна группа не заняла >10% набора.
- Выгрузка фиксирована файлами в `dataset/`; это срез прошлого, не live-API сайта.
- Почти нет персональных данных (на v2 замаскировано 5 строк: 1 телефон, 5 email). Стадия PII всё равно обязательна: ноль проверки ≠ ноль совпадений.
- Точных и near-дублей в этом источнике после нормализации вопроса почти нет (0 в метриках). Сама стадия нужна: `make check` подкладывает искусственные дубли и требует, чтобы они не прошли.
- Датасет не покрывает задачи классификации с короткими метками, диалоги длиннее одной пары user/assistant и не-статистические предметные области.
