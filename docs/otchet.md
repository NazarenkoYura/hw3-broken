## С чего начать чтение

1. `README.md` — цель и симптомы пяти дефектов.
2. `2-zadanie-dz3.html` — полное условие (7 слайдов).
3. `docs/datasheet.md` — что за данные.
4. `docs/defects.md` — разбор каждого бага.
5. `params.yaml` — единственная точка конфигурации (версии, пороги, пути).
6. `dvc.yaml` — граф: collect → clean → diversity → split.

Запуск:

```bash
uv sync
make repro          # весь пайплайн
make v1 / make v2   # переключить версию и пересчитать
make diff           # dvc metrics diff
make check          # восемь самопроверок
```

Данные (`dataset/`, `data/`) в git не входят. Нужны локальные CSV Cross Validated.

## Что уже было сделано до этой сессии

Стадия `collect` переписана с курсового НМО parquet на **свой** источник: три CSV Cross Validated. Контракт выхода тот же: JSONL chat.

Переработка источника (это и есть «свой» датасет, а не скачанный CSV):

- сужение до 125 тегов статистики/ML;
- ответ только если `Score ≥ 1`;
- пять системных промптов, выбор по sha1(id);
- HTML → текст.

Две версии: v1 = 2200 сырых строк (потолок 60 на тему), v2 = 6000 (потолок 120). После очистки: 2179 и 5934. Обе ≥ 1000.

## Как устроен пайплайн по файлам

- `src/collect.py` — CSV → `data/raw.jsonl`, метрики в `metrics/collect.json`.
- `src/schema.py` — валидация; битая строка: `файл:номер: причина`.
- `src/clean.py` — схема → длины → PII → точные дубли → near-dup.
- `src/pii.py` — телефон, email, дата рождения только с маркером «родился/д.р.».
- `src/dedup.py` — exact / MinHash LSH / cross-near для train vs test.
- `src/diversity.py` — гейт по порогам из params.
- `src/split.py` — группы-темы, запись train/val/test, отчёт контаминации.
- `scripts/check_contamination.py` — отдельный гейт для CI/`make contamination`.
- `scripts/set_version.py` — меняет одну строку `collect.version`, комментарии YAML не трогает.
- `tests/check.sh` — восемь проверок сдачи.
